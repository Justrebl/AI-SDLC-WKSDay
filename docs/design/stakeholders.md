# Stakeholders

This page lists who the workshop serves and who to involve before a delivery. Roles are described generically.

## Primary

| Role | Interest |
| --- | --- |
| Facilitator | Designs and delivers both workshops, and keeps the room in step |
| Advanced engineers | Hands-on attendees who want an end-to-end view of the AI SDLC |
| Wider technical audience (developers, tech leads, architects, product managers) | Attendees who follow the core path or a role track |

## Secondary

| Role | Interest |
| --- | --- |
| Environment owner | Prepares licences, repository access and plugin reachability before the day |
| GitHub organization and enterprise administrators | Control Copilot policies, model access, marketplaces, Copilot cloud agent, agentic workflows and Actions permissions |
| Template repository owner | Maintains the Music Catalog starter |

## Hidden

| Role | Interest |
| --- | --- |
| Security and compliance | Plugin trust, the APM supply chain, data sent to AI services and MCP servers |
| Accessibility owners | Consume the findings of the accessibility review workflow |
| Budget owner | Tracks Copilot, Copilot cloud agent and Actions usage |
| Upstream HVE-Core and APM maintainers | Their releases can change commands and break the scripted prompts |

## Consult before a delivery

- An organization administrator who knows which Copilot features and previews are enabled. Use the [kick-off call checklist](../kick-off-call-checklist.md).
- One or two target engineers to dry-run the scripted prompts and the timing.
